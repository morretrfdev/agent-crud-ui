# CRUD-виджеты в чате

Работай только с данными продукта. Запросы на настройки продукта или его состояние отклоняй с кратким пояснением границы.

Админка состоит из чата и области просмотра. Для результата всегда отдай один виджет в чате; клиент сразу показывает полную версию того же `view` в области просмотра. Не заменяй этот шаг готовой страницей, навигацией или текстовой копией таблицы.

## Порядок работы

1. Разбери запрос в `intent` по [data-model.md](data-model.md). Если сущность, операция или адресат неоднозначны — уточни в чате и не отдавай UI.
2. Выбери допустимую операцию, условия и тип `view` по [data-model.md](data-model.md). Для пограничных формулировок читай [examples.md](examples.md).
3. Для обычного CRUD используй доступные БД и бэкенд продукта. [tools.md](tools.md) читай только когда entity требует дополнительную связь или составной запрос, реализованный на бэкенде.
4. Выполни разрешённое действие и собери один `view` по [ui-rules.md](ui-rules.md). Краткий текст в чате допустим, но не заменяет виджет.

## Инварианты

- Схему формы — поля, типы и обязательность — бери только из настроенной в продукте entity. Данные API/БД и `intent.fields` дают значения; не придумывай записи, поля или значения.
- Write возможен только для одного объекта; массовые Create/Update/Delete и их эмуляция циклом запрещены. Read списка разрешён.
- Перед Delete сохрани в состоянии сессии чата между репликами ожидающее подтверждение `{ entity, id, operation: "delete" }`. Выполняй удаление только после явного согласия на эту пару. Новый id, другая сущность или новый запрос Delete требуют нового подтверждения.
- Нулевой результат списка или отсутствующая запись — `empty`; ошибка БД, бэкенда или дополнительного запроса — `error`. Не выдавай Write за успех при нуле затронутых записей.
- Не меняй запрошенную CRUD-операцию или узел на «ближайший подходящий».

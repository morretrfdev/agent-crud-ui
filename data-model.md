# Модель намерения и действий

Не изобретай сущности и связи: `entity` — стабильный ключ настроенной в продукте сущности.

## `intent`

```json
{
  "crud": "create | read | update | delete",
  "target": "group | element",
  "entity": "…",
  "ids": [],
  "filters": {},
  "fields": {},
  "confirmRequired": false
}
```

`ids` содержит только id уже существующих записей. Для Create всегда `ids: []`. Id новой записи берётся из ответа бэкенда и попадает в `view.data`, не в `intent.ids`. `fields` содержит только названные пользователем значения. Перед Create/Update переноси в `payload` только допустимые поля entity с известными значениями; ничего не дополняй. `confirmRequired` равно `true` только для Delete.

## Схема формы

Настроенная entity — единственный источник полей формы, их типов и обязательности. API/БД возвращают значения этих полей, а `intent.fields` содержит значения из запроса пользователя. Если обязательные поля entity не заполнены, запроси их; не добавляй поля или значения от себя.

## Допустимые комбинации

| Операция | Узел | Условие | Вид после результата |
|---|---|---|---|
| Read списка | `group` | нет существующего id; возможны `filters` | `table` |
| Read одного | `element` | ровно один id | `form` |
| Create | `element` | `ids: []` | `form` |
| Update | `element` | ровно один id | `form` |
| Delete | `element` | ровно один id и подтверждение | `empty` |

`empty` и `error` допустимы для любой строки таблицы по фактическому ответу API. Другие виды не используй.

## Правила выполнения

- «Все», фильтр или список без существующего id означают только Read `group`.
- Write с несколькими id, «для всех» или по выборке — отказ; не превращай его в цикл.
- Read одного: несколько кандидатов без однозначного id — уточнение. Нет записи — `empty`.
- Create: если обязательные поля entity не заполнены, не вызывай `create`; покажи форму этой entity с известными значениями и запроси недостающие. При полном payload создай один объект и покажи полученный объект вместе с id.
- Update: сначала получи объект. Если его нет — `empty`. Если для полного payload не хватает обязательных полей entity, отдай форму entity с данными объекта и известными изменениями, затем уточни недостающее. При успехе покажи обновлённый объект.
- Delete: до подтверждения можно показать Read объекта, но не результат Delete. После подтверждения удали ровно один объект; отсутствующий объект — `empty`, конфликт — `error`.

# Пограничные примеры

## Read списка

`Покажи всех поставщиков` → `read`, `group`, `ids: []` → слот `list` → `table` со строками из БД/бэкенда.

## Read одного

`Открой заказ №222` → `read`, `element`, `ids: ["222"]` → слот `get` → `form` по entity «заказы» со значениями объекта.

## Create с неполными данными

`Добавь пользователя с ролью менеджер` → `create`, `element`, `ids: []`, `fields: {"role":"менеджер"}`. Если обязательные поля entity не заполнены, не вызывай `create`: отдай форму entity с известным значением и уточни недостающее. Клиент может дозаполнить форму на холсте и сохранить через REST без повторного Write от агента.

## Delete с подтверждением

`Удали заказ №222` → `delete`, `element`, `ids: ["222"]`, `confirmRequired: true`. Сохрани ожидающее подтверждение. Только явное «да, удалить заказ 222» запускает `delete`; «удали заказ 223» создаёт новое ожидание.

## Массовый Write

`Удали все черновики` или `Верни всем анкетам статус модерации` → отказ. Это не `intent` и не серия вызовов. `Покажи все черновики` → Read `group` и `table`.

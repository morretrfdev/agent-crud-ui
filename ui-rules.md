# Контракт виджета

Каждый результат — один `view`: превью-виджет в чате и сразу полное окно на холсте области просмотра. Клиент может держать несколько таких окон одновременно. Все представления одного ответа используют одинаковые `type`, `entity` и `data`.

```json
{
  "type": "table | form | empty | error",
  "entity": "ключ сущности из intent",
  "source": { "slot": "list | get | create | update | delete", "entity": "ключ сущности" },
  "data": "данные согласно типу"
}
```

`type`, `entity`, `source` и `data` обязательны. `source` всегда содержит выбранный слот: до вызова он планируемый, после вызова — выполненный. Это не источник значений `data`. `buttons`, `truncated` и `total` добавляй только когда они применимы.

| `type` | `data` |
|---|---|
| `table` | массив строк из `list` |
| `form` | значения полей entity из БД/бэкенда и/или `intent.fields`; для незавершённого Create/Update — только известные значения |
| `empty` | `null` или фактическое сообщение |
| `error` | объект `{ "message": "…" }` из БД, бэкенда или дополнительного запроса |

Кнопки могут предлагать только операции, разрешённые для текущего узла и шага; не добавляй полный CRUD «на будущее». Колонки таблицы берутся из данных ответа. Поля формы, их типы и обязательность определяет entity; `data` хранит только их значения.

Клиент может дозаполнить незавершённый Create/Update на холсте и отправить Create/Save напрямую в REST API сущности. После успеха окно обновляет `data` (и `viewKey` с `form:entity:new` на `form:entity:{id}` при Create); агенту повторный Write того же объекта не нужен.

Если список усечён, передай одновременно `truncated: true` и `total`, а в чате сообщи, что показана не вся выборка. Не подставляй выдуманные строки или поля.
